# Alignment Memory 5분 라이브 데모 런북

## 데모의 한 문장

Alignment Memory는 번역기가 아니라, 서로 다른 시간대·언어·팀에서 나온 결정과 변경을 AI가 근거와 함께 연결해 다음 협업자가 같은 맥락에서 일하게 만드는 협업 메모리다.

## 사실 표시 원칙

- 실제 배경: 프로젝트 리드가 토론토에 체류하며 한국 개발자들과 비동기로 협업했다는 참가자 진술을 바탕으로 한다.
- 화면은 토론토·다낭·서울·도쿄에서 작업한 네 팀원의 역할을 재현한다. 네 사람이 실시간 접속한 것처럼 표현하지 않는다.
- 실제 작동 증거: GitHub 커밋·PR·Actions 실행, OpenAI 분석 결과, 원문 근거 링크, Handshake 기록을 화면에서 보여준다.
- 실패 이력도 지우지 않는다. 재현 가능한 오류와 수정 PR은 시스템이 실제로 개선된 협업 흔적이다.

## 녹화 전 준비

1. 브라우저 확대를 110~125%로 맞추고 개인 알림을 끈다.
2. 다음 탭만 순서대로 연다.
   - Alignment Memory 라이브 Preview
   - GitHub의 `demo-cross-border-agreement.md`
   - 충돌 데모 PR의 Actions 화면
3. Preview에서 GitHub 로그인과 저장소 연결을 완료한다.
4. Context Passport가 네 팀원 역할로 전환되고 표시 언어를 한국어·영어·일본어·베트남어 중에서 독립적으로 선택할 수 있는지 확인한다.
5. 충돌 데모 PR과 분석 결과를 미리 생성하되, 영상에서는 Actions 재실행 또는 결과 갱신으로 실제 동작을 보여준다.
6. 비밀키, `.env`, 브라우저 주소창의 인증 파라미터는 화면에 노출하지 않는다.

## 5분 타임라인

### 0:00–0:35 — 문제와 실제 배경

화면: 첫 화면과 Context Passport 역할 표시.

멘트:

> 저희는 토론토·다낭·서울·도쿄에서 한국어·영어·일본어·베트남어를 사용하며 협업했습니다. 거리보다 더 큰 문제는 한 언어로 합의한 결정이 다른 언어와 다음 작업 시간대로 넘어갈 때 이유와 근거가 사라진다는 점이었습니다. 지금부터 그 상황을 실제 팀 역할로 재현하겠습니다.

증명하는 기준: 문제 정의, 지리, 언어, 실제 협업 배경.

### 0:35–1:15 — 한국 팀의 결정이 근거가 되기까지

화면: `demo-cross-border-agreement.md`에서 한국어 개인정보 결정을 강조한 뒤 GitHub 커밋 기록을 짧게 보여준다.

강조할 원문:

> 원문 사용자 메시지는 외부 분석 서비스에 저장하지 않는다. 디버깅에는 익명화된 집계 지표와 재현 가능한 오류 코드만 사용한다.

멘트:

> 이 결정은 채팅 요약이 아니라 GitHub의 원문, 작성 이력, 커밋 SHA를 가진 검증 가능한 협업 근거입니다.

증명하는 기준: 조직 경계, 협업 흔적, 설명 가능성.

### 1:15–1:55 — AI가 프로젝트 메모리를 구성

화면: GitHub Actions의 Analyze 성공 → 앱의 Project Memory/Knowledge Graph.

멘트:

> OpenAI는 저장소 문서를 읽고 결정·제약·책임을 구조화합니다. 각 항목은 정확한 인용문과 GitHub 원문 링크를 가져야 저장됩니다. 그래서 AI가 그럴듯한 요약을 만드는 것이 아니라, 다음 작업에서 비교할 수 있는 프로젝트 메모리를 만듭니다.

증명하는 기준: AI 핵심성, 실현 가능성, 지식 구조화.

### 1:55–2:35 — 토론토 역할이 영어 변경을 제안

화면: 영어 제목의 충돌 PR.

예시 제목:

> `demo: add raw prompt logging for remote debugging`

예시 제안:

> Store full raw user prompts in a third-party analytics service so the Toronto developer can debug incidents asynchronously.

멘트:

> 한국 팀의 결정은 한국어였지만, 토론토 역할은 영어로 원문 프롬프트 저장을 제안합니다. 단순 번역으로는 문장은 이해해도 기존 합의와의 충돌까지 자동으로 찾기 어렵습니다.

증명하는 기준: 언어, 지리, 문화적 업무 방식의 차이.

### 2:35–3:25 — AI가 의미 충돌과 근거를 탐지

화면: Actions 완료 → Alignment Diff의 `Direct Conflict` → 한국어 원문 인용과 소스 링크.

멘트:

> AI는 영어 변경과 한국어 결정을 의미 단위로 비교해 직접 충돌로 분류합니다. 중요한 점은 결과마다 기존 결정의 정확한 인용과 원문 링크가 있다는 것입니다. 이 기능은 번역이나 키워드 규칙만으로 대체하기 어렵고, AI가 문제를 푸는 핵심 열쇠입니다.

증명하는 기준: AI 활용도, 보더리스, 설명 가능성.

### 3:25–4:10 — 네 역할이 같은 사실을 자기 맥락으로 확인

화면: Context Passport 역할과 표시 언어를 서로 독립적으로 전환.

멘트:

> 토론토·다낭·서울·도쿄의 팀원은 같은 근거를 자신의 역할 맥락에서 확인하고, 표시 언어를 직접 선택합니다. 시스템은 지역이나 국적으로 언어와 문화를 추측하지 않습니다.

증명하는 기준: 언어, 지리, 문화적 오해 방지, UI/UX.

### 4:10–4:40 — Handshake로 함께 결정

화면: `Needs clarification`을 남긴 후 해결안을 확인하고 `Agree`를 기록.

멘트:

> AI가 결론을 대신 내리지는 않습니다. 팀원이 질문과 동의를 남기고, 누가 어떤 근거를 확인했는지가 추적 가능한 협업 기록으로 남습니다.

증명하는 기준: 협업, 인간의 최종 결정권, 조직 경계.

### 4:40–5:00 — 가치와 확장성

화면: Project Memory 전체 화면 또는 네 경계 요약 슬라이드.

멘트:

> 번역 도구가 메시지를 옮긴다면 Alignment Memory는 팀의 결정을 다음 사람과 다음 시간대로 이어 줍니다. GitHub 조직·저장소 단위 SaaS로 확장해 글로벌 개발팀의 재설명, 잘못된 구현, 온보딩 비용을 줄이는 것이 목표입니다.

## 심사위원이 화면에서 확인해야 할 것

| 기준 | 화면 증거 |
| --- | --- |
| 지리 | 토론토·다낭·서울·도쿄의 비동기 인계 |
| 언어 | 한국어·영어·일본어·베트남어 사용과 교차언어 의미 충돌 탐지 |
| 문화 | 국적 추정 없이 사용자가 선택한 언어와 확인된 역할·시간대 사용 |
| 조직 | GitHub 저장소, 커밋, PR, 책임자, Handshake 연결 |
| AI 활용도 | 근거 추출 → 지식 구조화 → 교차언어 충돌 분석 → 역할별 Passport |
| 협업 | 실제 PR/Actions/수정 이력과 팀원의 확인 기록 |
| 실현 가능성 | 배포된 UI, API, OpenAI, GitHub Actions의 연결 |
| 시장성 | GitHub 조직·저장소 단위 팀 SaaS 확장 모델 |

## 실패 시 20초 복구 동선

- Actions가 늦으면 실행 중 화면을 3초 보여준 뒤, 미리 완료된 성공 실행 탭으로 이동한다. 완료된 결과를 새로 만든 것처럼 말하지 않는다.
- OAuth가 풀리면 GitHub의 성공한 Analyze/Publish 실행과 앱의 미리 생성된 결과를 차례로 보여준다.
- 네트워크가 끊기면 녹화해 둔 백업 클립을 사용하되 `사전 녹화된 동일 실행 결과`라고 표시한다.
- 어떤 경우에도 fixture를 live 결과라고 부르지 않는다.

## 녹화 합격 체크

- 5분 안에 문제 → 한국어 결정 → 영어 충돌 → AI 근거 → 팀원의 Handshake가 한 줄로 이어진다.
- 화면에 `role-play reenactment` 또는 동등한 안내가 보인다.
- GitHub Actions 성공, 원문 링크, 커밋/PR 중 최소 3가지 실제 증거가 보인다.
- AI가 한 일과 사람이 최종 결정한 일을 구분해서 말한다.
- 비밀키와 개인 인증 정보가 한 프레임도 노출되지 않는다.
